# إصلاح خطأ صلاحيات حفظ المنتجات

## الهدف
تحديد عملية قاعدة البيانات أو التخزين التي تُرجع خطأ RLS عند حفظ المنتج، ثم إصلاح مسار التفويض فقط دون تغيير التصميم أو تعطيل RLS.

## التنفيذ
1. تتبع زر «حفظ» في نافذة المنتجات الحالية والتأكد من الوظيفة الفعلية التي يستدعيها، مع حصر كل العمليات التابعة للحفظ ورفع الصورة.
2. إضافة تشخيص آمن داخل مسار الخادم يربط الخطأ باسم العملية والجدول (`products` أو أي جدول/تخزين تابع) بدل تمرير رسالة عامة مبهمة.
3. توحيد كل عمليات كتابة المنتج عبر Server Functions محمية؛ التحقق من دور الأدمن/الموظف باستخدام جلسة المستخدم، ثم تنفيذ الكتابة المصرح بها من الخادم فقط.
4. فحص إعداد عميل الخادم ومفتاح الخدمة الفعلي، ومنع أي fallback إلى المفتاح العام أو عميل المستخدم في مرحلة الكتابة.
5. حذف أو تعطيل أي مسار حفظ قديم/مكرر ما زال قابلًا للاستدعاء من واجهة المنتجات الحالية، دون المساس بمسارات القراءة.
6. اختبار إضافة منتج، تعديل منتج، تغيير صورته، وحذفه، مع فحص الطلبات والسجلات لتأكيد العملية والجدول النهائيين.
7. تشغيل فحص الأنواع والاختبارات وبناء نسخة Node، ثم إعادة البحث داخل المصدر والحزمة الناتجة عن أي كتابة مباشرة قديمة.

## تفاصيل تقنية
- لن يتم تعطيل RLS أو توسيع سياسات الجداول أو التخزين.
- لن يظهر مفتاح الخدمة في ملفات العميل أو ناتج البناء.
- إذا تعذر الاختبار بحساب مسجل داخل هذه البيئة، ستُذكر حالة مسار المستخدم المسجل صراحةً كغير متحققة بدل الادعاء بنجاحها.
