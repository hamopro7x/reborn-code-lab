# جدول بيانات الشغل — خطة التنفيذ

## أولًا: مراجعة البنية الحالية (تم)

- **الموظفون**: يُعرَّفون عبر `user_roles` (`app_role = admin | employee`) + `profiles` (الاسم، الإيميل، الصورة). الإدارة في `EmployeesTab` داخل `src/routes/_authenticated/admin.tsx` عبر `src/lib/admin.functions.ts`. الـ User ID هو `auth.users.id`.
- **الأجهزة المصرح بها**: جدول `user_devices` (بصمة الجهاز + `hw_signature`) ويتم فحصه في بوابة `_authenticated/route.tsx` عبر `checkDevice`. أجهزة برنامج الموظف في `agent_devices`.
- **المعاملات**: مزامنة خلفية في `src/lib/bybit.server.ts` تكتب كل الحركات في `bybit_ledger` (`kind`: card / onchain / internal / p2p_buy / p2p_sell) ومنع التكرار عبر `ref_id`. معاملات الفيزا الخام في `bybit_card_txns` (`txn_id`). العرض في `BybitLedgerPanel.tsx` عبر `getBybitLedger`.
- **P2P**: يُجلب من `/v5/p2p/order/simplifyList` ويُخزَّن في `bybit_ledger` بنفس الشكل.
- **الصلاحيات**: `assertAccess` في `bybit-access.ts`؛ مشاركة الأقسام مع الموظفين عبر `site_settings.employee_panels`.

**نتيجة المراجعة**: `bybit_ledger` هو المصدر الجاهز للمعاملات، فلن نلمسه ولا نلمس أي حقل أصلي. سنبني طبقة منفصلة فوقه.

## ثانيًا: قاعدة البيانات (جداول جديدة فقط)

1. `work_shifts` — `id, user_id, started_at, ended_at, ended_reason, verified_face, verified_device, created_at`.
   قيد: شفت واحد فقط مفتوح في النظام كله (Unique Index على `ended_at IS NULL`).
2. `work_txn_assignments` — الربط بين المعاملة والشفت:
   `id, ledger_id (FK bybit_ledger), shift_id, user_id, assigned_at, assigned_by, assign_mode ('auto' | 'manual')`.
   `ledger_id` **UNIQUE** → المعاملة تُربط مرة واحدة فقط ولا تُحسب مرتين.
3. `employee_face_enroll` — بصمة الوجه المرجعية للموظف (تُخزَّن كمتجه/صورة مرجعية في bucket خاص) + `webauthn_credentials` لمصادقة الجهاز (public key فقط، لا بصمات).
4. دوال SECURITY DEFINER: `work_claim_shift(...)` (تنهي الشفت الحالي وتبدأ شفتًا جديدًا ذريًا)، و`work_assign_txn(...)` (ربط يدوي للمدير فقط).
   كل جدول مع `GRANT` + RLS: الموظف يقرأ سجله، المدير يقرأ الكل.

## ثالثًا: استلام الشغل (التحقق)

- **تحقق الوجه**: تسجيل صورة مرجعية للموظف مرة واحدة (Enrollment) من لوحة المدير، ثم عند الاستلام تُلتقط صورة من الكاميرا وتُقارن على السيرفر عبر Lovable AI (موديل رؤية) وتُعاد نتيجة نجاح/فشل فقط.
- **مصادقة الجهاز**: WebAuthn platform authenticator (Face ID / Touch ID / Android Biometric) — تسجيل مفتاح للجهاز، ثم توقيع تحدٍّ عند كل استلام. لا تُخزَّن أي بصمة.
- بعد نجاح الاثنين → `work_claim_shift` تنهي شفت الموظف السابق في نفس اللحظة وتبدأ شفت المستلم الجديد.

## رابعًا: الربط بالمعاملات

- المعاملات غير P2P: عند دخولها من المزامنة تُربط تلقائيًا بالشفت المفتوح لحظة الإدخال (`assign_mode='auto'`)، وليس بحسب وقت المعاملة.
- **P2P**: لا تُربط تلقائيًا. تظل ظاهرة لجميع الموظفين في قسم P2P كما هي. بعد اكتمالها يظهر للمدير زر «ربط بالشفت» → قائمة الموظفين/الشفتات → يُحفظ الربط، ثم يُعطَّل الزر نهائيًا لهذه المعاملة (يمنعه قيد UNIQUE على مستوى قاعدة البيانات أيضًا).

## خامسًا: الواجهة — قسم جديد «جدول بيانات الشغل»

قسم مستقل في لوحة الإدارة (لا تغيير في أقسام المعاملات الحالية):
1. **من ماسك الشغل الآن** — الموظف الحالي، وقت البداية، المدة الجارية، عدد معاملات الشفت + زر استلام الشغل للموظف.
2. **الشفتات** — الموظف، البداية، النهاية، المدة، عدد المعاملات؛ فتح الشفت يعرض معاملاته.
3. **الجدول** — نفس أعمدة «جميع المعاملات الخارجية» + أعمدة الموظف/الشفت/طريقة الربط.
4. **الإنتاجية اليومية والأسبوعية** — لكل موظف صف لكل يوم وإجمالي أسبوعي؛ كل رقم قابل للضغط ويفتح قائمة المعاملات الفعلية المكوِّنة له.
5. **تفاصيل المعاملة** — نفس عرض التفاصيل الحالي (البيانات الأصلية كما هي) + الموظف والشفت المرتبطين.

الأرقام كلها محسوبة من صفوف `work_txn_assignments` الحقيقية، بلا أي Counter، فلا يُصفَّر شيء ولا تُفقد أيام سابقة.

## ملاحظة تحتاج تأكيدك

تحقق الوجه على الويب يحتاج صورة مرجعية مسجَّلة لكل موظف حتى تصح المقارنة. الخطة تعتمد: تسجيل الصورة المرجعية من لوحة المدير + مقارنة على السيرفر. لو تحب طريقة أخرى (مثل رفع الموظف صورته بنفسه، أو الاعتماد على مصادقة الجهاز فقط) قل لي قبل التنفيذ.
