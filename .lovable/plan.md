# تشغيل Bybit Sync على VPS مع قاعدة Lovable Cloud الحالية

## النتيجة المباشرة

لا توجد طريقة رسمية لاستخراج `SUPABASE_SERVICE_ROLE_KEY` أو Secret Key للمشروع الحالي `shrrrgvcrevujivuyvzv` من Lovable Cloud، ولا توجد لوحة Supabase أو Organization يمكن فتحها لهذا المشروع من حسابك الشخصي. المفتاح الإداري وكلمة مرور قاعدة البيانات مُداران داخليًا وغير متاحين للتنزيل أو العرض.

يمكن للـVPS الاتصال بواجهة قاعدة Lovable Cloud باستخدام عنوان المشروع والمفتاح العام الموجودين في إعدادات التطبيق، لكن هذا الاتصال يخضع لـRLS ولا يمنحه صلاحيات إدارية.

## لماذا المفتاح العام لا يكفي لمزامنة Bybit الحالية

المزامنة الحالية تحتاج إلى:

- قراءة حسابات Bybit.
- قراءة مفاتيح كل حساب من `private.bybit_account_keys` عبر `bybit_account_get_keys`.
- الكتابة في جداول المعاملات وحالة المزامنة.

الكود الحالي ينفذ ذلك بعميل إداري يعتمد على `SUPABASE_SERVICE_ROLE_KEY`، كما أن دوال قراءة مفاتيح Bybit مخصصة لصلاحية `service_role`. لذلك لا يمكن تشغيل **نفس المزامنة الحالية مباشرة على VPS** باستعمال الـpublishable/anon key فقط.

## الطرق المتاحة بدون إنشاء مشروع Supabase جديد

### الخيار 1 — إبقاء التنفيذ داخل Lovable Cloud

يجعل الـVPS يستدعي الرابط الحالي:

```text
POST https://www.mag-pro1.com/api/public/hooks/bybit-ledger-sync
```

لكن تنفيذ المزامنة سيظل داخل Lovable، وبالتالي لن يحقق هدف إيقاف Run Credits. كما أن `SYNC_HOOK_SECRET` يجب أن يكون مضبوطًا داخل بيئة التطبيق وعلى الـVPS بالقيمة نفسها؛ لا يمكن استخراج سر موجود من Lovable.

### الخيار 2 — تعديل آمن لاحقًا للسماح للـVPS بالمزامنة دون مفتاح إداري

هذا هو المسار الوحيد مع الاحتفاظ بقاعدة Lovable Cloud وعدم إنشاء قاعدة جديدة:

1. إنشاء هوية خدمة مخصصة للمزامنة في Auth، وليست حساب موظف عادي.
2. إضافة صلاحيات قاعدة ضيقة جدًا لهذه الهوية فقط.
3. إنشاء RPC واحدة محمية تنفذ دورة المزامنة المطلوبة أو تمنح البيانات الضرورية بأقل صلاحيات ممكنة.
4. يجعل الـVPS يسجل الدخول بهوية الخدمة ويحصل على JWT قصير العمر، بدل امتلاك `service_role`.
5. تشغيل Bybit worker على الـVPS واستدعاء قاعدة Lovable Cloud مباشرة عبر HTTPS.
6. اختبار النتائج ودقة الـlease ومنع التكرار.
7. إيقاف Cloud Job فقط بعد نجاح الاختبار.

هذا المسار يحتاج تعديل كود وmigration أمنية، لذلك لم يُنفذ الآن بناءً على طلبك.

### الخيار 3 — نقل قاعدة البيانات إلى بيئة تملك مفاتيحها

هو الحل المطلوب إذا أردت وصولًا إداريًا كاملًا من الـVPS، لكنه يتطلب قاعدة جديدة تملكها أنت أو Backend مستضافًا ذاتيًا، وهو خارج شرطك الحالي.

## الخلاصة العملية

- لا يوجد مكان رسمي داخل Lovable للحصول على Secret/Service Role Key للمشروع الحالي.
- لا تطلب المفتاح من الدعم ولا تحاول استخراجه من ملفات المتصفح؛ المفتاح غير مُتاح للمستخدم في Lovable Cloud.
- ربط الـVPS بالمفتاح العام ممكن للعمليات التي تسمح بها RLS فقط، وليس للمزامنة الحالية.
- بدون أي تعديل: الخيار الوحيد هو استدعاء الـhook المنشور، وسيظل يستهلك Run Credits.
- لإزالة Run Credits مع إبقاء قاعدة Lovable Cloud: يلزم تنفيذ الخيار 2 بتعديل محدود وآمن، وليس كشف المفتاح الإداري.

لم يتم تعديل أي كود أو إعداد أو بيانات، ولم يتم إيقاف Cloud Job.
